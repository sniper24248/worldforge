# 移动端（方案 C）开工备忘

> 2026-10-24 记。当天额度见底，先不动手。这份是给"下个月的我"看的，目标是一次开工不返工。

## 定位

**看 + 记**，不做 **画 + 生图**。手机是"灵感和查阅"，不是"制作"。

| 保留 | 砍掉 |
|---|---|
| 设定卡浏览、搜索、单卡轻编辑 | 生图工坊（整块） |
| 时间线查看 | 地图画区域 / 连线 / 拖顶点 |
| 关系图查看（可拖节点，不可连线） | 关系图连线、力导向整理 |
| 地图查看（双指缩放、平移） | 设置里的通道配置 |
| 世界切换、快速记录 | 导入 txt |

## 形态

独立的一套移动页面，**不动桌面版**：

```
public/
├─ index.html          # 桌面版，保持原样
├─ m/index.html        # 移动版入口
├─ m/app.js            # 移动版逻辑（可复用 store/api 的部分函数）
└─ css/mobile.css      # 独立样式，不背桌面版的包袱
```

访问 `http://<电脑IP>:7317/m`。服务端已经能托管静态文件，不用改后端（除了下面那条增量接口）。

## 页面清单（5 个）

1. **今日 / 最近改动** —— 最近编辑的 8 张卡 + 今天的时间线事件
2. **卡片列表** —— 搜索框 + 类型筛选（横向 chips）+ 单列卡片
3. **卡片详情** —— 标题、类型、标签、字段、正文（可只读，编辑走弹层）
4. **时间线** —— 纵向时间轴（不是桌面那种横向泳道），按年份倒序
5. **地图** —— 只读 SVG，双指缩放、单指平移、点图钉看卡片

底部 4 个 tab：卡片 / 时间线 / 地图 / 更多（世界切换、设置只读）。

## 后端要加的一条接口

现在写卡是**整份 world PUT**（44 张卡 = 68 KB），手机上每次改一个字都传 68 KB，不合适。

新增：

```
PATCH /api/world?world=<id>   body: { entityId, patch }
```

只改一张卡；服务端读出整份 JSON、合并、原子写回。前端移动版只调这个。
（桌面版不用改，继续整份 PUT。）

## 技术上必须处理的坑

- `touch-action: none` 只加在地图/关系图的画布上，否则整页不能滚
- `100dvh` 代替 `100vh`（iOS 地址栏）；`env(safe-area-inset-bottom)` 给底部 tab 留位
- 键盘弹出时不要顶起 tab（`position: fixed` + `visualViewport` 监听）
- 输入框字号 ≥ 16px，否则 iOS 会自动放大页面
- 拖动和滚动冲突：地图容器内 `overscroll-behavior: contain`
- 卡片正文用 `-webkit-line-clamp` 截断，别整段渲染 4 万字
- 首次加载只取列表需要的字段（`/api/world` 支持加 `?fields=summary` 之类的话更省，可选）

## 验收标准

- [ ] 手机上能打开 `/m`，首屏 1 秒内出内容（局域网）
- [ ] 卡片搜索、打开详情、改一句话并保存，电脑上刷新能看到
- [ ] 时间线纵向滚动不卡
- [ ] 地图双指缩放正常，页面本身不会被一起缩放
- [ ] 键盘弹出时底部 tab 不遮挡输入框
- [ ] 桌面版 `/` 完全不受影响

## 开工顺序（省额度的写法）

1. 先写后端 PATCH 接口 + curl 验证（便宜、确定性强）
2. 一次写完 `m/` 三个文件
3. 只截 2 张图核对布局，改一轮
4. 再截 2 张做最终确认
